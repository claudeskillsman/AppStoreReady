# Contributing to AppStoreReady

Thanks for helping. AppStoreReady is a community project, and the most useful contributions are:

- **False-positive reports.** A finding that is wrong for your project, with a minimal example.
- **New rules** that catch real submission problems, backed by Apple documentation.
- **Fixtures** that reproduce real-world project layouts (CocoaPods, SPM, multi-platform, tvOS, watchOS).
- **Updates when Apple changes a requirement**: SDK lists, required-reason codes, deployment targets, background modes.

## Getting started

You need Swift 5.9 or later (Xcode 15+ on macOS, or a Swift toolchain on Linux).

```sh
swift build
swift test
swift run appstoreready scan Tests/Fixtures/Hardening
```

The fixture projects in `Tests/Fixtures` are generated by `Scripts/generate-fixtures.py`. Change the script, not the generated files:

```sh
rm -rf Tests/Fixtures && python3 Scripts/generate-fixtures.py Tests/Fixtures
```

## Adding or changing a rule

1. Read the "Contributing" and "Checks" sections of the [README](README.md).
2. **Cite Apple.** Every rule needs at least one `Reference` to a developer.apple.com page that supports it. Only call something an Apple requirement when that page says so. If you can't find an Apple source, make the finding a best-practice (`INFO`) or manual-review item and say so in the pull request.
3. **Be honest about certainty.** A `verified-issue` must be read directly from project configuration with high confidence. Anything inferred from text matching is a `potential-issue`.
4. **Never print secrets.** Findings must not include secret values or parts of them.
5. **No execution, no network.** Rules read the `ScanContext` only. `SecurityModelTests` checks for forbidden APIs.
6. **Test both cases.** Add a fixture or extend one, and test the failing and the passing case.
7. **Rule IDs are permanent.** Use the next free `ASRnnn` and never reuse one.

## Pull requests

- Keep each pull request focused on one change.
- Run `swift test` before opening it. CI runs on macOS and Linux.
- Update the README rules catalog and `CHANGELOG.md` when behavior changes.

## Reporting security issues

See [SECURITY.md](SECURITY.md). Please don't open a public issue for a way to make AppStoreReady execute code, reach the network, or leak a secret.

## Code of conduct

Be kind and constructive. This project follows the [Contributor Covenant](https://www.contributor-covenant.org/version/2/1/code_of_conduct/), version 2.1. Report unacceptable behavior to the maintainers through a private GitHub security advisory or by contacting a maintainer directly.
